# small/r23: MP256 v1 (R14 card MP256), built on small/r22 (r22 untouched)

Status: SOURCE ONLY (uncompiled, no GPU); NOT to be built on GPU until r22's stop-rule measurements P1-P7 confirm the model (card section 0). Covers local m = 1..256 (target 129..255, T = 516..1020). X1, every R12 mechanism, the overhead round (TAG_EARLY, POLL_BATCH, IK_PAR_REL) and the test seams are kept; all r22 options stay (B_QUAD, BN128, RX3 are REQUIRED at MP256: `#error` otherwise).

## Geometry
- `SM_MP = 256`, `SM_ITERS = MP/128 = 2`, `SM_NPASS = 8` (passes per 128-row chunk, the r22 role counts), `SM_NPASS_TOT = 16`. P `[3][256][N]` = 28.3 MB dense / 30.3 MB indexer, reuse. **Rx `[2][3][256][F]` (3 slots) = 7,077,888 B (dense) / 7,864,320 B (indexer, reuse): it does NOT fit the 4 MiB view of r22 and fits the 8 MiB view** (4 slots would be 9.4 / 10.5 MB). static_assert: 4 MiB < SM_RX_BYTES <= 8 MiB, exact values, X-5 slack 0. aiter must budget the 8 MiB view for r23.
- RAN grid unchanged from r22: **228 (dense, reuse) / 248 (indexer)**, all <= 256 resident; K per (src,dst) = 16 (+4 IK) unchanged.

## GEMM BM256 x BN128, SK3, PFK3
- 6 waves (384 threads): 2 producer + **4 consumer waves x MT4** (accumulators 4 tiles x EN8 = 128 floats per wave, as r22). Consumer wave `cw_all` -> `hi = cw_all >> 1` selects rows `128*hi ..`, `cw = cw_all & 1` the 16-row group of each 32-row tile; tile t of the wave covers rows `128*hi + 32*t + 16*cw + 0..15`, live iff `8*hi + 2*t + cw < AQ` (AQ = ceil(M/16) in 1..16, dispatch to `gemm_body<1..16>`; MT = 4 for AQ > 8). Per output element the MFMA chain and K order are exactly r22's (P byte-identity vs the BM128 reference on rows 0..127 / 128..255 is gate N-2).
- Stage = A 32 KiB + B 16 KiB = 48 KiB, PFK3 = 144 KiB LDS, 1 WG/CU; grid 216 / 231 WGs. `MB = BQ + AQ <= 24`, `(PFK-2) * MB = 24 <= 63` (static_assert). **Found while doing this: the vmcnt immediate is 6 bits (max 63); r22's `wait_newer` default arm computes `4 * MB` = up to 64 at AQ = 8, which may not compile for the AQ = 7/8 instantiations. r23 clamps dead arms (`wn<MB,K>`) and asserts the live ones; r22 is unchanged (told to the Lead).**
- Driver launches the GEMM with `SM_GEMM_THREADS` (384).

## RAN roles: 2 iterations per WG (global pass = chunk pass + 8 * iteration)
- Every role body is wrapped in `for (itr = 0; itr < SM_ITERS; ++itr)`; `pbase` gains `8 * itr`. A **dead iteration** (`8*itr >= ceil(M/16)`) loads no P / Ascale (`live_it`), stores nothing, but keeps the control path so ONE-TIME duties are never skipped.
- **push / IK owner:** early tag stored in the first iteration (with the first data), data stores every iteration, the per-wave `vmcnt(0)` + barrier after each, and the release **once after the last iteration** (K unchanged, release count unchanged).
- **self:** the whole body per iteration. **B octo (= B quad x 2 iterations):** flag poll / acquire and the tag check happen ONCE (first iteration; later iterations reuse `s_ticket` and `s_tagbad` from LDS); a dead octo (all its iterations dead) still polls and acquires; per-iteration `live_pass = (8*itr + 4*qd) < passes`. Each iteration re-reads the entry ERR/epoch (same batch) and re-runs `decide`.
- `SM_TEST_RX_BEFORE_FLAG`: the seam preloads per iteration before its (skipped at itr > 0) poll, so it bites the first iteration only.

## Update after the r22 GPU result: BN64 is the r23 default (BN128 optional)
- **GPU fact (formal, two windows):** r22 with `gemm_bn128=0` is the best MP128 arm (T512 C 60.2-61.1 us, 1.19-1.23x); BN128 is a net loss (68 us; GEMM 200 -> 360 VGPR + 128 AGPR). So r23 no longer requires BN128: `SM_GEMM_BN128` default 0; the MP256 `#error` now only requires `SM_RX3` + `SM_B_QUAD`. BN128 stays selectable (BM256 x BN128, PFK3, 216 / 231 WGs).
- **Choice: BM256 x BN64 in ONE kernel (4 consumer waves x MT4), PFK4** over "2 M-tiles of the r22 BM128 x BN64 GEMM".
  - Per-wave footprint is identical to the r22 BN64 GEMM (MT4 tiles x EN4 bands = 64 accumulator floats, same va/vb), so the ~200 VGPR of the measured arm is expected, not the 360 of BN128.
  - Traffic (SK3, K = 6144, dense; A rows are re-read by every N-tile): one BM256 tile: A 226 MB + W 57 MB = 283 MB; two BM128 tiles: A 226 MB + W 2 x 57 = 113 MB = 339 MB, and twice the WGs (864 / 924).
  - Time (M3 models: H1 bytes at ~10.5 TB/s, H2 = 16 K-blocks / (PFK-1) x ~2.0 us per round): **BM256xBN64 PFK4** = 432 / 462 WGs at 1 WG/CU = 2 rounds x (16 / 3 x 2.0 = 10.7 us) ~ 21 us (H2) .. 27 us (H1); **2 x BM128xBN64 PFK3** = 864 / 924 WGs on 512 slots = 2 rounds x 16 us ~ 32 us (H1 and H2). Forecast [inference]: single BM256 kernel saves ~5-11 us. `-DSM_GEMM_PFK=3` (120 KiB, 2 in flight) degrades it to ~32 us = the 2-M-tile figure, i.e. the fallback costs nothing extra.
  - **Risk:** PFK4 = 4 x (32 KiB + 8 KiB) = **160 KiB, exactly the per-CU LDS limit** (static_assert `LDS_BYTES * WG_PER_CU <= 163840` holds with zero slack); if the toolchain rejects a 160 KiB static array, use PFK3. Occupancy is 1 WG/CU (the GEMM grid 432 / 462 > 256 CUs = ~2 rounds; the RAN kernel starts after it).
- vmcnt: BN64 PFK4: MB = 4 + AQ <= 20, live (PFK-2) * MB = 40 <= 63 (asserted); dead arms clamped (`wn<MB,K>`).
- Checks: `check_r23_static.py` (BN128 requirement dropped; BN64 default, PFK4 and SM_GEMM_PFK asserted), `check_r23_roles.py` (both BN options: WGs, rounds, LDS 160 / 144 KiB) ALL PASS.

## SM_P_NT (R14-r22-stamps-analysis C1): non-temporal 16 B P stores (default 0 until validated)
- GEMM epilogue: the lane's 4 accumulators of a (tile, band) are 4 consecutive ROWS of one column (opus `C:[(rept_c<y>, grpm_c<p>, pack_c<y>), (grpn_c<p>)]`, pack_c = 4, acc index stride 1; read from `opus.hpp`). A 4x4 transpose across the quad of adjacent lanes (DPP `quad_perm` 0x4E / 0xB1: 4 dpp movs + 8 selects + 4 dpp + 4 selects) yields 4 consecutive COLUMNS of one row = 16 B contiguous, stored with `__builtin_nontemporal_store` (SM_P_NT=1, `global_store_dwordx4 ... nt`) or inline `global_store_dwordx4 ... sc0 sc1 nt` (SM_P_NT=2, system write-through + streaming). Per instruction: 16 rows x 64 B segments (4 lanes per row); the 4 bands of a tile fill adjacent 64 B segments of the same 256 B row span. Values and reduction order are untouched (pure data movement) => P byte-identical; gate = the M3 P compare. `0` = the scalar store; `SM_P_NT` and the r15 `SM_NT_STORES` are exclusive.
- **Coherence with the RAN's P loads (reasoning, not verified on HW; I could not fetch the ISA doc here):** the epilogue already ends with `s_waitcnt vmcnt(0)` (stores acknowledged before the WG exits), and the next kernel's plain loads rely on the kernel-boundary acquire/release, exactly as for today's regular (L2 write-back) stores. nt only changes the cache replacement/streaming policy of the store; SM_P_NT=2 additionally uses the system-scope write-through bits (the same sc0|sc1 flavour the push16 stores already use for peer windows), so no dirty P can remain in the producing XCD's L2. Evidence should confirm (a) ISA shows `global_store_dwordx4 ... nt` (and sc0 sc1 for 2), (b) the G1 / P byte-compare passes over many replays, (c) the gap and GEMM span change (falsifier of the C1 writeback model).
- **SM_SK (C2):** already a build knob (`SM_SK_CFG` 2|3, `-DSM_SK_CFG=2`); not changed. SK2 = P -33 %, K loop 24 blocks per WG, P NOT byte-identical to SK3 (tolerance-gated; byte-exact only against an SK2 reference).

## Indexer RAN spill (Evidence r23 ISA: VGPR 256 + 378 spills, 780 B scratch; dense/reuse 207 VGPR clean; r22 indexer 184)
- **Role (source analysis; I cannot compile here): the IK OWNER.** It is the only role that exists solely in the indexer build (dense/reuse compile the same push / self / B code with 0 scratch), and it is the role whose body (3-destination push + early tags + parallel release + the head-19 self fusion with the RowPre/rope/RMS state) is the largest. The r23 change that affects it is the 2-iteration loop.
- **Mechanism (hypothesis):** with `SM_ITERS = 2` as a compile-time constant the loop was fully unrolled, so the compiler could hoist iteration 2's P/Ascale loads (pk[3][2][8] = 48 floats + ws + as_) above iteration 1's push / self fusion (loads may move above a release fence), overlapping two iterations' working sets: ~100 extra live VGPRs on top of 184, matching +378 spill instructions at the 256 cap.
- **Fix applied:** all four iteration loops carry `_Pragma("clang loop unroll(disable)")` (the iterations stay a real loop: iteration 2's loads depend on the loop variable and cannot be hoisted into iteration 1) plus `__builtin_amdgcn_sched_barrier(0)` at the top of each body (no scheduler motion across the boundary).
- **Per-role attribution tool (if the spill persists):** `-DSM_DIAG_ROLE_MASK=<bits>` (default 15; bit0 IK, bit1 push, bit2 self, bit3 B) compiles a role body out; build the indexer with 14 (no IK), 13, 11, 7 and read VGPR / scratch from `-Rpass-analysis=kernel-resource-usage` to see which role sets the peak. Diagnostic only, behaviour with a role removed is wrong by design.
- **Fallbacks if it still spills (not applied):** (a) compute the IK self-fusion rows in the NEXT iteration's slot instead of holding `vv` (re-load P: one extra read of 48 floats per row), (b) run the two IK iterations as two sequential IK WGs per owner (grid +4: 252, still <= 256), (c) `__launch_bounds__(512, 1)` does not raise the 256-VGPR cap (2 waves/SIMD), so it is not a lever.

## Spill-fix attempt reverted; fallbacks prepared (opt-in, default 0)
- **Reverted** (`ee882324`): `unroll(disable)` + `sched_barrier` made dense/reuse worse (207 VGPR / 0 scratch -> 256 VGPR / 232 spills) and the indexer only slightly better (378 -> 302 spills). The iteration loops are plain loops again; `SM_DIAG_ROLE_MASK` is kept. Wait for Evidence's masked builds (14 / 13 / 11 / 7).
- **(a) `SM_IK_RELOAD_P=1`:** the IK owner pushes from a scoped local `vp`; its self fusion re-loads P / Wscale / Ascale and recomputes `vv` (the pushed values and the 48-float `pk` are not live across the push stores, the barrier and the release). Costs one extra P read of 48 floats per row.
- **(b) `SM_IK_SEQ=1`:** two IK WGs per owner, one iteration each (no loop in the IK role): `SM_T1_IK_WGS` 4 -> 8, grid 248 -> 252 (<= 256), K per (src,dst) 20 -> 24 (asserted generically by `kcount`); owner `o` covers passes `{2(o%4), 2(o%4)+1} + 8*(o/4)`; a dead IK WG (iteration 1 at M <= 128) still releases. The two macros can be combined.
- Static / model checks cover both (defaults unchanged: 0).

## Push live-set options (Evidence attribution on the reverted source: the indexer spill is the PUSH role; mask 13 -> 154 VGPR / 0 scratch; IK off / ik_seq / ik_reload_p cannot pass)
- **SM_PUSH_PASSTRIP (default 0), push role only:** the push round is split into two sub-trips of ONE pass each: `pk[SK][3][1][8]` = 72 floats instead of 144. Sequence per iteration: sub-trip 0 = loads (P pass 0, Wscale, Ascale, epoch/ERR/tag/credit) -> ONE wait -> decide -> barrier -> early tag + reduce/stores of pass 0 -> sub-trip 1 loads (P pass 1) issued while the pass-0 stores are in flight -> one `vmcnt(0)` that covers BOTH (stores + loads are overlapped) -> reduce/stores of pass 1 -> the usual wait + barrier + release. Decide, the early tag and the release stay once; sub-trip 1 is skipped when its pass is dead (`pbase + 1 >= passes`, wave-uniform, no barrier inside). Latency cost: one extra P-load round trip per iteration minus its overlap with the pass-0 store retire (estimate +1.2-1.5 us per iteration, [inference]). The ISA gate "exactly one vmcnt(0) before decide" still holds; there is a second vmcnt(0) after the decision.
- **SM_PUSH_WS_LATE (default 0):** Wscale (3 x 8 floats) is loaded in its own short trip after the decision (`ok && live_it`) instead of with the P loads: -24 live floats while the 144 (or 72) P floats are in flight, +~0.8 us. Works alone or with PASSTRIP.
- Both are plain macros (aiter-integrator exposes them as params, indexer only). The default path is the unchanged `#else` branch (byte-identical source to before).
- **`ik_reload_p` showing byte-identical metrics:** the code path is reachable (`if (ok && live_it)` in the IK role, `SM_IK_VV vp`); the IK owner is not the register peak (push is), so changing IK live ranges leaves the kernel's VGPR / scratch totals unchanged. (I cannot confirm that the macro reached the compiler: `build_device.sh` VARDEFS does not list it, aiter's JIT flag list must.) Dead IK options can stay as ablations.

## R16 pad-M (device decide)
- `decide()` now rejects `4 * M > SmDev.T` instead of `SmDev.T != 4 * M`: the launch M (SmRanArgsV3.M, GEMM args.M, both per-launch kernargs) may be any 1 <= M <= the bucket M the binding was made for. Everything else already derives from the launch M (t = s*M + m, live = m < M, rowc clamps, passes, GEMM AQ / A rows / P rows, Ascale rows); SmDev only carries T (this check), strides and pointers. Host: `sm_launch_blk_v3m(..., m, ...)` in the shared driver (m = 0 = bound M).
