# small/r22: tuned MP128 (R14 F1), built on small/r21 (r21 untouched)

Status: SOURCE ONLY (uncompiled, no GPU). Design: `records/architecture/stage3/R14-m65-255-design.md` + `r14-parts/f1-small-mp-tuning.md`; reviewer conditions `records/reviews/R14-review-r1.md` (binding). Covers local m = 1..128. Every R12 mechanism, the X1 restrict `blk` parameter, the tags and the test seams of r21 are kept. Outputs must be byte-identical to r21 (gate G1); each option is a compile-time switch, default ON, the old behaviour selectable for the A/B.
NOTE: r21 does not contain the r19/r20 overhead round; it has been PORTED into r22 (see the last section).

## Options (ABI `sm_abi_v3.h`)
- **SM_B_QUAD (1)** option (1) residency. B WG = (src, head, 4-pass quad) on all 8 waves; half hf = tid >> 8 owns passes {4qd + 2hf, 4qd + 2hf + 1}; B_SPLIT = NPASS/4 = 2 => B WGs 108 / 120 and RAN grid **228 (dense, reuse) / 248 (indexer)** <= 256 resident WGs at 1 WG/CU. `=0`: r21 (one pass per B WG, 552 / 608).
  - **B-2 (mandatory):** the I-1 retire predicate now reads `wgid >= PUSH_WGS && (!SM_B_QUAD || wgid < B0) && wave >= 4`: waves 4-7 of the B-quad WGs stay alive (IK/self WGs still retire theirs).
  - **B-3:** the halves run head_row concurrently, so head_row must be LDS-free and barrier-free: `#error` unless SM_RMS_ORDER 3/4 with SM_AMAX_REG=1 (SM_LDS_LEGACY = 0 and SM_HEAD_TAIL_SYNC = 0). `tests/check_lds_protection.py` rerun on this source: every configuration PASS, default order 3/4 + AMAX_REG=1 = **0 LDS ops, 0 barriers**; the negative control bites.
  - **B-1:** coverage asserts rewritten in `t1_roles.hpp` (`b_cover_ok` over (head, quad), `B_PER_PAIR * NH == HEADS_SRC * B_SPLIT`, NH1 grid sums, quad grids 228 / 248, `SM_T1_GRID <= 256`).
  - **B-4:** one wait (all Rx loads and the tag load are one batch) and ONE tag decision: each wave compares the tag, a mismatch sets the shared `s_tagbad` (+ `set_err(0x30)`), one barrier, then both halves see `ok = false` and NaN-fill.
  - **B-5:** a dead quad (`4*qd >= ceil(M/16)`) still polls and acquires flag[src] but loads no Rx, checks no tag and stores nothing (`live_pass`); head_row stays guarded by the global pass `(pbase + pass) < passes` for half-dead quads.
- **SM_GEMM_BN128 (1)** option (3). GEMM BM128 x BN128, SK3, PFK4 (stage A 16 KiB + B 16 KiB = 32 KiB, 128 KiB LDS, 1 WG/CU), 72 / 77 N-tiles x 3 = **216 / 231 WGs** (<= 256, one round). The r18 tiled MMA per 32-row tile is unchanged; each consumer wave holds MT = 4 tiles x EN = 8 bands = 128 accumulator floats; the producer issues BQ = 8 B instructions per K block (MB = 8 + AQ); every output element keeps the r18 MFMA sequence and the K-order of the split (kb_begin/kb_end untouched) => **P byte-identical to r21** (the M3 compare is the gate). `SM_GEMM_NTILES = N' / BN` (N' = 9216 for REUSE_NO_IDX else N). `=0`: BN64, PFK3, 2 WG/CU (r21).
- **SM_RX3 (1)** option (4). Rx indexed by remote ordinal `rx_ord(s, d) = s < d ? s : s - 1` (3 slots; the never-used self slot dropped): Rx `[2][3][128][F]` = **3,538,944 B (dense) / 3,932,160 B (indexer, reuse)**, i.e. inside the OLD 4 MiB view (r21 needed 8 MiB at 4 slots: 4,718,592 / 5,242,880 B). `=0`: 4 slots.
  - **C-1:** ONE helper `rx_ord(s, d)` at the 2 writer sites (push `rx_ord(rank, d)`, IK owner) and the 5 reader sites (B WG `rx_ord(s, rank)`); `rxord_bijective()` static_assert over all 12 (s, d) pairs.
  - **C-2:** `rx_view` is `[2][SM_RX_SLOTS][MP][F]`, `SM_RX_BYTES = 2*SLOTS*MP*F*2`, the window assert (3 slots <= 4 MiB / 4 slots needs 8 MiB) and the exact X-5 values for both slot counts change together; the host `RX_BYTES = SM_RX_BYTES` (aiter must size the Rx window from `sm_info_v1[0]`; the integrator can use the 4 MiB view for r22 defaults).
  - **C-3:** control-window indices (flag[rank], tag[par][rank], credit words) stay RANK-indexed.
- **SM_PUSH_PAR (0, NOT built)** option (2): per review A-9 (96 push WGs + B-quad blow residency) it stays at the 48 push WGs; setting it is an `#error`. `t1_roles.hpp` is already generic in PAR / AGG_N (releasers = push WGs / AGG_N), for the later implementation under A-1..A-8 (A-1: a member counts only after a complete ok push).

## Overhead round ported (same patch as r19/r20; defaults 1)
- **SM_TAG_EARLY (1):** the releasing thread stores its tag(s) in the same batch as its push16 data (push tid 0; IK owner: lane 0 of each releasing wave); the per-wave `vmcnt(0)` retires them, the later fence has nothing outstanding; D-2 holds (same thread, before its own fence). `SM_TEST_TAG_AFTER_RELEASE` (G10b) requires `SM_TAG_EARLY=0` (#error otherwise).
- **SM_POLL_BATCH (1):** `poll_range64` issues the flag and ERR loads back-to-back, one wait; flag value is checked first.
- **SM_IK_PAR_REL (1):** the IK owner releases its 3 destinations from lane 0 of waves 0/1/2 after the vmcnt(0) + barrier, each storing its own tag early.
- **Stamps:** 36 release begin, 38 early tag issue, 39 B poll start, 40-42 IK per-destination release done, 43 B source label (stamps build only). Static checks extended (31 -> 38 assertions). `=0` keeps the previous behaviour for each switch.

## B-quad vs r21 nh=2 (what to expect, and the A/B to run)
- r21 ships `B_HEADS=2` (216 / 240 B WGs, grid **336 / 368** > 256 resident). Per B WG critical path in r21 nh=2: 2 heads x ONE pass per wave (two head_row bodies after one load batch). r22 B-quad NH1: 1 head x TWO passes per wave (two head_row bodies after one load batch): the SAME per-WG body, but the grid is **228 / 248 <= 256 resident**, so the residency overflow tail that dominates nh=1 -> nh=2 (73-77 -> 64-66 us) disappears while the per-WG body stays equal. Plus BN128 GEMM (-5 us forecast), 3-slot Rx and (if ported) fewer releases.
- Selectable alternatives (all supported by the coverage asserts and `tests/check_r22_roles.py`): **`B_HEADS=2` with B_QUAD** (B WG = 2 heads x 4 passes: 54 / 60 B WGs, grid **174 / 188**, per-WG body 4 head_rows per wave), `B_HEADS=2 -DSM_B_QUAD=0` (= r21 nh=2 geometry, grid 336 / 368). Suggested formal A/B at T512: r21 nh=2 | r22 NH1 quad | r22 NH2 quad | r22 NH1 quad with `-DSM_GEMM_BN128=0` (separates the GEMM term). Default stays B_HEADS=1 (build_device.sh); the aiter owner/variant for r22 should pass `nh` explicitly.

## vmcnt immediate fix (after Evidence/r23 review)
- `wait_newer` used `s_waitcnt_vmcnt(number<k * MB>)` for k = 1..4 with MB = BQ + AQ; at BN128 MB = 8 + AQ reaches 16, so the DEAD default arm (4 * MB = 64 at AQ = 8) exceeded the 6-bit vmcnt immediate (max 63). Live values are newer <= PFK-2 = 2 (<= 2 * 16 = 32). Now `wn<MB,K>()` clamps dead arms and `static_assert((PFK-2) * MB <= 63)` guards the live ones. No change in emitted live behaviour. r21 (BN64, MB <= 12, max 4 * 12 = 48) is not affected.

## SM_P_NT (R14-r22-stamps-analysis C1): non-temporal 16 B P stores (default 0 until validated)
- GEMM epilogue: the lane's 4 accumulators of a (tile, band) are 4 consecutive ROWS of one column (opus `C:[(rept_c<y>, grpm_c<p>, pack_c<y>), (grpn_c<p>)]`, pack_c = 4, acc index stride 1; read from `opus.hpp`). A 4x4 transpose across the quad of adjacent lanes (DPP `quad_perm` 0x4E / 0xB1: 4 dpp movs + 8 selects + 4 dpp + 4 selects) yields 4 consecutive COLUMNS of one row = 16 B contiguous, stored with `__builtin_nontemporal_store` (SM_P_NT=1, `global_store_dwordx4 ... nt`) or inline `global_store_dwordx4 ... sc0 sc1 nt` (SM_P_NT=2, system write-through + streaming). Per instruction: 16 rows x 64 B segments (4 lanes per row); the 4 bands of a tile fill adjacent 64 B segments of the same 256 B row span. Values and reduction order are untouched (pure data movement) => P byte-identical; gate = the M3 P compare. `0` = the scalar store; `SM_P_NT` and the r15 `SM_NT_STORES` are exclusive.
- **Coherence with the RAN's P loads (reasoning, not verified on HW; I could not fetch the ISA doc here):** the epilogue already ends with `s_waitcnt vmcnt(0)` (stores acknowledged before the WG exits), and the next kernel's plain loads rely on the kernel-boundary acquire/release, exactly as for today's regular (L2 write-back) stores. nt only changes the cache replacement/streaming policy of the store; SM_P_NT=2 additionally uses the system-scope write-through bits (the same sc0|sc1 flavour the push16 stores already use for peer windows), so no dirty P can remain in the producing XCD's L2. Evidence should confirm (a) ISA shows `global_store_dwordx4 ... nt` (and sc0 sc1 for 2), (b) the G1 / P byte-compare passes over many replays, (c) the gap and GEMM span change (falsifier of the C1 writeback model).
- **SM_SK (C2):** already a build knob (`SM_SK_CFG` 2|3, `-DSM_SK_CFG=2`); not changed. SK2 = P -33 %, K loop 24 blocks per WG, P NOT byte-identical to SK3 (tolerance-gated; byte-exact only against an SK2 reference).

## Push live-set options ported from r23 (opt-in, default 0, push role only)
- `SM_PUSH_PASSTRIP` (two single-pass sub-trips: pk[SK][3][1][8] = 72 floats instead of 144; the second sub-trip's loads overlap the retire of the first sub-trip's stores, one `vmcnt(0)` covers both; decide, the early tag and the release stay once; the second sub-trip is skipped when its pass is dead) and `SM_PUSH_WS_LATE` (Wscale in a short trip after the decision). Same structure as r23 (no iteration loop in r22: `live_it` / `itr` guards dropped). r23 GPU result (lead): PASSTRIP=1 fixes the indexer spill (161 VGPR, 0 scratch) and is faster in every mode (dense/reuse -2.6..-5.6 us), so it is worth an A/B on the shipped MP128 slot. Default path is the unchanged `#else` branch. Static check extended (+1; early-tag sites 3, rx_ord 8 because the macro branch repeats the push site text). Not compiled here.

## R16 pad-M (device decide)
- `decide()` now rejects `4 * M > SmDev.T` instead of `SmDev.T != 4 * M`: the launch M (SmRanArgsV3.M, GEMM args.M, both per-launch kernargs) may be any 1 <= M <= the bucket M the binding was made for. Everything else already derives from the launch M (t = s*M + m, live = m < M, rowc clamps, passes, GEMM AQ / A rows / P rows, Ascale rows); SmDev only carries T (this check), strides and pointers. Host: `sm_launch_blk_v3m(..., m, ...)` in the shared driver (m = 0 = bound M).
