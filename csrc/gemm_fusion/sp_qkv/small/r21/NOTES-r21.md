# small/r21: MP128 (R13 card MP128 variant), built on small/r20 (r20 untouched)

Status: SOURCE ONLY (uncompiled, no GPU). Covers local m = 1..128 (target 65..128, decode T = 260..512). All R12 mechanisms (kernarg v3, tags by the releasing thread, ERR/NANMODE, t_valid pad, set_err reasons < 0x100) and r20's role structure are kept; SM_RX_BYPASS = 1 and SM_NO_CREDIT = 1 are still required.

## Geometry
- `SM_MP = 128`, `SM_NPASS = 8`. P `[SK][128][N]`: dense 14,155,776 B, indexer/reuse 15,138,816 B at SK3. **Rx `[2][4][128][F]`: dense 4,718,592 B (4.5 MiB), indexer/reuse 5,242,880 B (5.0 MiB) = it does NOT fit the 4 MiB view of MP64: the arena Rx view must be 8 MiB** (static_assert: 4 MiB < SM_RX_BYTES <= 8 MiB). aiter-integrator budgets the 8 MiB view. X-5 (highest Rx vector access == window, slack 0) asserted for both F. `SM_DBG_RAN_MAXWG` 1024 (grid <= 608).
- **GEMM BM128 / SK3 / PFK3** (design of the M3 bench, which passed: P byte-equal, BM128 16.2 us at m=128): AQ = ceil(M/16) in 1..8, MT = (AQ+1)/2 <= 4 accumulator tiles per consumer wave (r18 tiled MMA per 32-row tile), per-16-row-group dead mask `2t + cw < AQ`, stage = A 16384 + B 8192, PFK3 = 72 KiB LDS (2 WG/CU = 144 KiB <= 160 KiB; PFK4 would be 96 KiB = 1 WG/CU), `wait_newer` newer in [0, 1], refusal `M > SM_MP`. Grid 432 / 462 WGs. (The M3 data say BM128 is also cheaper than BM64 at m=64: 10.3 us; whether to serve 33..64 from the MP128 build is the integrator's call.)

## Roles (global pass = pbase + local pass; local arrays keep 2 passes, so register use per role is unchanged from r20)
- **push**: 48 WGs x 512 thr = 24 unit WGs x 2 row groups (WG w: unit WG `w % 24`, row group `w / 24` owns passes {4g..4g+3}; half hf = tid >> 8 owns {4g+2hf, 4g+2hf+1}). Each WG owns 2..3 units of ONE destination, one round trip, one wait, pk 144 floats, ONE release (tag stored by the releasing thread). 6 push WGs per XCC (r20: 3) => the release queue per XCC doubles (M2: ~0.6 us per extra release). **K = 16 unit pushers** per (src,dst).
- **IK owners** (indexer): FOUR WGs, owner o owns passes {2o, 2o+1}; each pushes its rows to all 3 destinations and releases once per destination: **K = 16 + 4 = 20** (dense/reuse 16). Every owner releases even if its rows are dead (the count must be exact).
- **self**: WG k = (head h = k / 4, row group sp = k % 4) owns passes {2sp, 2sp+1}: 72 / 76 WGs.
- **B**: one head-group x ONE pass per WG (B_SPLIT = 8, NH1): 432 / 480 WGs. Dead pass (rsp >= ceil(M/16)): flag acquire only, no Rx load, no tag check, no stores. Every (src,dst) pair keeps >= 1 acquiring WG at every m in 1..128.
- **Grid** (NH1): dense/reuse 48 + 72 + 432 = 552; indexer 48 + 4 + 76 + 480 = 608.
  **OCCUPANCY CAVEAT (new):** the 512-thread launch with VGPR <= 256 gives 1 WG per CU (8 waves) = 256 co-resident WGs, so the grid exceeds residency (r20's 276 / 304 already did). WGs beyond residency start as earlier ones retire. No cyclic wait is possible: every WG waits only on flags released by PUSH/IK WGs of OTHER ranks, and push/IK WGs are the lowest wgids (dispatched first, in order) on every rank and never wait. This relies on in-order dispatch of workgroup ids; dead-pass B WGs retire quickly. Evidence should include a hang test at m = 128 and consider `B_HEADS=2` (216 / 240 B WGs, grid 336 / 368) as an A/B (coverage asserts and the model support both).
