# small/r20: MP64 (R13 card A r2), built on small/r19 (path A: r19 is the only base; r19 untouched)

Status: SOURCE ONLY (uncompiled, no GPU). Covers local m = 1..64 (the target is 33..64, decode T = 132..256). Every R12 mechanism of r19 is kept (kernarg v3, tags stored by the releasing thread, ERR read at entry and in polls, NANMODE, t_valid pad, set_err reasons < 0x100). Card: `records/architecture/stage3/R13-card-a-mp64-r2.md` (D2 table, R2.3-R2.5).

## What changed vs r19
- **SM_MP = 64, SM_NPASS = 4** (ABI `sm_abi_v3.h`): P `[SK][64][N]` (dense 7,077,888 B, indexer/reuse 7,569,408 B at SK3), Rx `[2][4][64][F]` = 2,359,296 B (dense) / 2,621,440 B (indexer, reuse), both <= the 4 MiB arena view; `rx_view`/`p_view` are SM_MP-strided; `SM_DBG_RAN_MAXWG` 128 -> 512 (grid 276 / 304).
- **GEMM BM64 / SK3 / PFK4** (`device/sk_gemm_fp8.cu`, `device/layout/sk_traits.hpp`): the r18 tiled MMA (TM2, EM1, EN4) is unchanged; BM64 holds MT = 2 accumulator tiles per consumer wave (tile t = rows t*32 + cw*16..+15, MFMA per tile and K block), so every output element sees exactly the r18 MFMA sequence (P expected byte-identical to the BM32 x 2 reference; this is the M3 bench's design, `bench/m3_gemm_bm.cu`). AQ = ceil(M/16) in 1..4 (producer A instructions, MB = 4 + AQ), dead-row mask per 16-row group (`2t + cw < AQ`), ring PFK4 (A 8192 + B 8192 per stage, 64 KiB LDS, 2 WG/CU), refusal `M > SM_MP`. `wait_newer` handles newer in [0, 4] (PFK4 uses [0, 2]).
- **RAN roles (512-thread launch; waves 4-7 of every non-push WG retire, I-1)** with the generalised pass mapping `global pass = pbase + local pass` (all local arrays keep 2 passes; the 15 row expressions and both head_row guards use it):
  - **push** 24 WGs x 512 thr: half hf = tid >> 8 owns passes {2hf, 2hf+1}, all 2..3 units of ONE destination; one round trip, one wait; pk stays 144 floats; K = 8 unit pushers.
  - **IK owners** (indexer): TWO WGs, owner o owns passes {2o, 2o+1}, pushes its rows to all 3 destinations and releases once per destination (tag by the releasing thread) => **K = 8 + IK_WGS = 10** for every (src,dst) pair (dense/reuse 8); both owners release even when their rows are dead (the count must be exact).
  - **self** row split: WG k = 2h + sp, head h, passes {2sp, 2sp+1} (36 / 38 WGs).
  - **B** row split: one head-group x ONE pass per WG (B_SPLIT = 4, NH1 default now): 216 / 240 WGs. **Dead pass (rsp >= ceil(M/16)): the WG still polls and acquires flag[src] but loads no Rx, does no tag check and stores nothing** (`live_pass`).
  - the r15-r18 shape switches (PUSH8, PUSH_HALVES, B_ROWSPLIT) are removed (setting them is an `#error`); `decide()` no longer refuses M <= 16 for the row split (dead passes allowed, M >= 1).
- **SM_RX_BYPASS = 1 is REQUIRED in every mode** (`#error` otherwise): the gfx950-only hardware dependency of r18 R2 (sc0|sc1 Rx loads, no buffer_inv, including the tag load) now extends to ALL small modes at MP64 (card D-10). Release notes must say so. SM_NO_CREDIT must stay 1.
- build_device.sh default `B_HEADS=1` (NH1), as the 216/240 B WG counts assume.

## Static checks (source level, all PASS)
- `tests/check_r20_roles.py` (independent Python model): grids 276 / 304 (<= 512 slots); push covers every (dst, unit, pass) exactly once by the two halves; K = 8 (+2 IK) for every (src,dst); IK owners cover passes {0..3} once; self (head, pass) once; B (src, head, pass) exactly once on all 4 ranks and every (src,dst) pair keeps >= 1 acquiring WG for m in {33, 40, 48, 49, 63, 64} (dead passes acquire); Rx 2,359,296 / 2,621,440 B <= 4 MiB and X-5 (highest Rx vector access == window, slack 0); GEMM grid 432 / 462 <= 512; LDS 64 KiB x 2 <= 160 KiB; push partial registers 144.
- `tests/check_r20_static.py` (23 source assertions): 3 release_tagged sites, ERR read in 4 entry rounds, tag/NaN in both B paths, pass expressions all global, dead-pass B WG skips loads/tag but keeps the acquire, no PUSH8/HALVES/ROWSPLIT left, RX_BYPASS required, MAXWG 512, IK_WGS 2, GEMM BM64/PFK4/dispatch/mask/stamps.
- C++ `static_assert`s (compile-time, unrun): `kcount(r) == 8 + IK_WGS` (indexer 10, dense/reuse 8), `SM_B_SPLIT == SM_NPASS`, `SM_SELF_SPLIT*2 == SM_NPASS`, `IK_WGS*2 == SM_NPASS`, grid = push + IK + self + 3*B_PER_PAIR (276 / 304 for NH1), `SM_RX_BYTES <= 4 MiB` with the exact dense / indexer values, X-5 bound, `b_cover_ok()` over (head, pass), `SM_RX_BYTES == [2][4][MP][F] bf16`.
- LG-C18 `check_directives.py` and a brace/paren balance pass on the kernel, GEMM, traits and ABI headers.

## Unverified / risks (for Evidence and the lead)
1. NOT compiled. First-compile risks: the BM64 GEMM (opus tiled MMA with per-tile accumulators; the M3 bench has the same construct and has not been compiled either); `x[kk][pass]` arrays leave the non-active local pass uninitialised (never read); the `SM_BPASS_ON(pp) ((pbase + (pp)) == rsp)` guards inside unrolled loops.
2. Gate M3 (P byte-identical to the BM32 x 2 reference, GEMM end <= 12.5 us), M2 (24x512 vs 48x256), the ISA gates per role under the 512-thread bound (no scratch, exactly one `s_waitcnt vmcnt(0)` before decide in push/self/B, VGPR <= 256), the R2 bypass gates X-1..X-6 and control (iv) per mode, WAR seams and the skip-acquire control with K = 8 / 10, dead-pass test at m = 33 with R12 tags active, `.02` + K-byte numerics at m in {33, 40, 48, 49, 63, 64} x 3 modes incl. padded t_valid < M, reuse index_cache untouched.
3. Wasted work by design at small M: push half 1 (rows 32..63) and IK owner 1 do clamped loads when m <= 32; stores are masked. Timing at m = 33..48 is expected to be dominated by the dead-pass overhead only in the push WG.
4. Self/B/IK still hold `s_row[16*128]` (16-row LDS) per WG: no LDS growth.
5. The host side is unchanged from r19 (`sm_attach_v3`, `sm_launch_blk_v3` in the shared fusion driver); aiter-integrator owns the MP64 owner/profile rows. `bind` accepts M up to 64 through SM_MP.
## Test seam added after Evidence control (iv) (default 0, preprocessor-only: the code object is byte-identical when the macro is 0)
- `SM_TEST_DELAY_PUSH_DATA=<n>`: every wave of the push WGs and IK owners sleeps n x s_sleep(127) BEFORE issuing its push16 DATA stores (the flag release is not delayed). Usable alone; intended together with `SM_TEST_RX_BEFORE_FLAG=1` (needs `SM_RX_BYPASS=1`; default in r20/r21, explicit in r19) so that the pre-flag bypass loads observe stale/torn Rx. n=20 is about 80 us.
