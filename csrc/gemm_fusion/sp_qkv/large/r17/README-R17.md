# large/r17: FlyDSL GEMM with a destination-major BF16 epilogue (R18 r13, route B)

Status: SOURCE ONLY (uncompiled, no GPU, no FlyDSL on the authoring box). Evidence runs `microbench_r17.py`.

## What it is
`flydsl_dstmap_gemm.py` = `aiter/ops/flydsl/kernels/preshuffle_gemm.py` (the 4-wave preshuffle FP8 GEMM; sha256 recorded in the file header) with ONE new compile option `dst_map` (`"none"` | `"dense"` | `"indexer"`), GENERATED by `tools/derive_dstmap.py` (every edit asserts its anchor; `tests/check_r17_static.py` re-derives and compares when the aiter checkout is present). With `dst_map != "none"` the epilogue
1. scales in the r13 / PR695 ptpc order `bf16_rne( fp32( fp32(acc * Ws) * As ) )` (the stock FlyDSL epilogue multiplies `(acc * As) * Ws`: different fp32 rounding, so it is switched for dst_map),
2. writes each lane's bf16 element (scalar 16-bit buffer store, the proven ragged-N store path) to `S[dst][row][F]` through the golden field map: raw column n -> Q `n // 2048`, K `(n-8192) // 128`, V `(n-8704) // 128` (dense F = 2304, N = 9216; packed columns Q 0..2047, K 2048.., V 2176..); indexer (F = 2560, N = 9856) adds IQ `(n-9216) // 128` at packed 2304.. and IK (raw 9728..9855) REPLICATED to all four destinations at packed 2432..;
3. slab stride = the launch's M rows (`S` is `[4][M][F]` flat bf16, slab d at `d*M*F` elements), rows >= M and columns >= N are redirected to the one-past-end element (dropped by the descriptor), as in the stock ragged path.
Completion is the kernel boundary ("all done"); no arrival counters (at ~1 wave there is no overlap to exploit).

The (dst, packed) base is computed once per 16-column MFMA block (a block never straddles a 128-column field segment; the 192-wide tile is a multiple of 16 only, so the map is per block, not per tile). `mirror_dstmap.py` is the independent readable map; `tests/check_r17_static.py` proves it is a bijection onto S (IK x4) and that the kernel's select chains equal it for every 16-column block.

## Run (Evidence)
```
python microbench_r17.py --m 384 450 512 700 --n 9216 9856 --tile 477 236 --iters 100          # random data, <= 1 bf16 ulp check
python microbench_r17.py --m 384 512 --n 9216 9856 --tile 477 --exact                           # small-integer data, BYTE-EXACT check of the layout
```
Tile 477 = `flydsl_bpreshuflle_112x192x256_F8_F8_B16_1x1x4x2` (async copy 1, waves_per_eu 1, xcd_swizzle 4, lds_stage 2); tile 236 = `..._128x192x256_..._1x0x4x2` (waves_per_eu unset). The harness prints, per case, the stock-epilogue time (BASE, the same kernel with `dst_map="none"`, row-major `[M, N]`; the reference to match, ~41.5 us at M = 512) and the dst-map time, plus the check status. N = 9856 is ragged for tile_n = 192 (51.3 tiles): the existing ragged-N machinery applies.

## Targets / expectations (all inference)
Target: dst-map time ~= BASE time (the epilogue is a store re-addressing; the stores stay 16-bit scalar buffer stores with 16 contiguous lanes per row). Risk: the scalar-store epilogue is the same cost class as the stock ragged path; if BASE uses a vectorized store path for exact-N shapes, DST at N = 9216 may be slower than BASE (the harness shows the delta). A later step could pack the four rows a lane owns into one wider store through a quad transpose, as large/r13 and small/r22 do.

## Unverified
Never compiled: the FlyDSL frontend restrictions (runtime `if` for the IK replication with nested `range_constexpr` stores, `Int32` floor division / modulo, `.select` chains) are written to the skill's rules but unproven; first-compile failures are expected to be local to `_dst_pack_*` and the store block.
## BG-1: system-scope release before the SDMA put (option `sys_release`, default True)
Reviewer BG-1 (records/reviews/R18-r18put-review.md): the SDMA engine does not snoop the XCD L2s, so S must be written back before the put kernel's SDMA read. With `dst_map != "none"` and `sys_release=True` (default) the S stores use `CPOL_COHERENT` (sc0|sc1 write-through: no dirty S line is left in any XCD L2) and every wave ends the epilogue with `s_waitcnt(0)` (vmcnt 0 = all its stores complete): the same release idiom as FlyDSL's own split-K epilogue (`splitk_epilogue.py`: "the store carries sc0|sc1, so waiting on it is the whole release", no agent fence / L2 flush). This is the flydsl equivalent of `buffer_wbl2 sc0 sc1 + s_waitcnt vmcnt(0)` without writing back unrelated dirty lines. `sys_release=False` = plain stores (A/B: `microbench_r17.py --no-sys-release` prints the cost of the release; Evidence re-times it). `--exact` stays byte-exact (the policy changes no value). Unverified: that FlyDSL's `BufferCopy16b(CPOL_COHERENT)` lowers to `buffer_store_short ... sc0 sc1` and that sc0|sc1 write-through is a sufficient release for the SDMA read on gfx950 (the reviewer's premise; I could not check the ISA here).
