# large/r18-put: the PUT kernel of the r17 pipeline (route B)

INTERNAL-ONLY. Source only, uncompiled: Evidence builds and runs it. Tree = a copy of large/r13 (device, ABI, host driver, scripts; **ABI version, ctl layout, R12 protocol, quiet_ready and the r13 GEMM entries are byte-identical**, proved by `tests/check_r18put_static.py`) plus ONE new entry `lg_put_v1`.

## Launch order per call (one stream, graph-capturable)
1. **r17 flydsl GEMM** writes `S[dst][row][F]` (dest-major BF16, golden field map, IK replicated) with slab stride `srows` rows = its LAUNCH M (m_real <= srows <= the plan bucket M).
2. **`lg_put_v1`** (grid = 1 + 15 blocks x 512 threads): block 0 = poster (waves 0..2, one issuing lane each: credit -> credit wait + tag check -> ONE put of the peer's slab (live rows) -> quietQueue -> arrival release); blocks 1..15 = self copy S[rank] rows [0, m_real) -> R[rank * m_real ..] (what r13's GEMM epilogue did by writing the self tile straight into R).
3. **`lg_quiet_ready_v2`** (r13 code, unchanged): W2 for the three peers + tag check + device-side reset + epoch advance; NaN fill under ERR; **launched with `args.M = m_real`** so its r13g self compaction (`if m_real < M`, which assumes the BUCKET slab stride) is off: the put kernel did the self copy with the real slab stride.

## ABI / host (what the plan wires)
- Same `LgCommArgsV4` (360 B), same attach (`lg_attach*`, one HSACO). The put kernel reuses the struct: `strideA` carries **srows** (`LGP_SROWS(a)`), `reserved[0] = LG_R18_PUT_PLAN_CODE` (0x20000 | indexer bit 0x100), `reserved[1]` = wait budget us, A / W / scales unused (null), `chunks = M / 256` and every other field exactly as `lg_comm_launch` fills them.
- `LG_ENTRY_PUT = "lg_put_v1"`; `LgCommCtx::fput` is resolved at create (a missing symbol fails the attach); `lg_put_launch(h, srows, poll_budget_us, call_id, m_real, stream)` (tree driver) and, in the shared driver `sp_qkv/host/lg_fusion_driver.cpp`, **`lg_put_launch_v1`** with the same arguments (compiled only when the ABI header defines `LG_ENTRY_PUT`, i.e. only for this tree; r13 / r14 images are unaffected). It enqueues the put kernel and then quiet_ready; return codes as `lg_comm_launch` plus -111 (no put entry), -106 (srows outside [m_real, M]).
- Window sizing is unchanged: S sized for 4 * M * F BF16 of the plan bucket (srows <= M), R = [4 * m_real, F] compact as r13.

## ORDER PROOF (for the reviewer). Notation: K_g = the r17 GEMM, K_p = lg_put_v1, K_q = quiet_ready, e = the epoch word, E = (STEP << 32) | call_id.
- **O1 data -> put source.** Every S store of K_g precedes K_p's start (one stream). The SDMA engine reads memory, so K_g's stores must be at memory (not only in a CU's L2) before the put: this rests on the end-of-kernel release of K_g (agent scope, L2 writeback of every XCD) completing before K_p is dispatched. r13 achieved the same by an explicit system-scope release in `x_publish` before each counter increment; here the kernel boundary replaces it. **Assumption A1 (hardware/runtime, reviewer please confirm): HIP's same-stream kernel boundary on gfx950 includes the L2 writeback.** Test: Evidence byte-exact runs (R == reference for all four sources) over many iterations; a stale-source failure would show as old-epoch rows.
- **O2 credit before put (unchanged from r13).** wave w: store credit TAG (relaxed system) -> release-store CREDIT to the peer (fence + vmcnt(0) + store, `st_u64_rel_x`) -> bounded wait for the PEER's credit >= e (ERR-aware) -> check the peer's credit tag == E (mismatch => ERR TAG_CREDIT, no put) -> arrival tag store (LG_TAG_EARLY) -> ERR re-check -> put. The peer's credit e means its quiet_ready of epoch e-1 has already advanced EP, i.e. the receiver consumed R of e-1: no WAR on R.
- **O3 put -> arrival.** put (queue 0) -> `quietQueue` (CCO claim C6: the put completed at the destination, also implies the local source read is done) -> ERR re-check -> release-store ARRIVAL[rank] = e on the peer. The peer's K_q W2 waits ARRIVAL >= e and atag == E, hence all of this rank's rows are in its R.
- **O4 self slab.** Blocks 1..15 of K_p write R[rank * m_real ..]; K_q starts only after K_p completes (stream order), the receiver reads R only after K_q: the self rows are visible to it. The copy is skipped when ERR is already set at K_p entry (K_q then NaN-fills R); a copy that started before ERR appeared finishes before K_q begins, so a K_q NaN fill always lands AFTER it.
- **O5 quiet_ready unchanged.** K_q runs with `q.M = m_real`: only the self-compaction condition differs; W2 / reset (the gdone / state words are zero and unused here) / epoch advance / NaN fill / drain are r13 code. Peers' arrival counts are exactly 1 per epoch per peer (one put per peer), as r13 with n = 1.
- **O6 error paths.** Config mismatch (`r18_put_cfg_ok`: abi, items_per_group, queues, chunks, plan code, N, F, err/step pages, qr_wgs, m_real range, srows in [m_real, M], pad4 == 0) poisons CONFIG in block 0 / thread 0 and returns before any credit: the peers' W1 waits time out and poison, as r13. ERR sticky checks before credit, before the put and before the arrival, as r13; fail() drains the queue before returning after a put was issued.
- **O7 S is free after K_p.** Each lane drains its queue before it releases its arrival, so every read of the local S by the SDMA engine is complete when K_p ends: the next call's GEMM may overwrite S.
- **O8 byte accounting.** put bytes = 2 * m_real * F, source offset peer * 2 * srows * F (inside slab `peer` because srows >= m_real), destination offset rank * 2 * m_real * F: the four senders (self by copy) tile R = [4 * m_real, F] exactly once (`check_r18put_static.py` model, dense and indexer F, m_real 1..768).

## Risks / open points
Uncompiled. A1 above. `strideA` is overloaded for `srows` (documented, guarded by the plan code). quiet_ready's `M` contract is enforced by the launcher, not by a device check. No overlap of the puts with the GEMM exists in this pipeline (separate kernels): the hiding of the card is gone by construction; the cost is the full wire time after the GEMM.

## Negative-control seams (r18-put)
- **Apply to `lg_put_v1` (reimplemented with the r13 semantics in `r18_put_poster`):** `LG_X_TEST_BAD_CTAG`, `LG_X_TEST_BAD_ATAG`, `LG_X_TEST_CTAG_AFTER_RELEASE`, `LG_X_TEST_ATAG_AFTER_RELEASE` (+ `LG_X_TEST_TAG_DELAY_ITERS`). (v1 of this tree carried these macros only in the inherited GEMM poster, so they compiled but were INERT for the put path; fixed in the follow-up commit.)
- **N/A by design:** `LG_NEGCTRL_NOWAIT` (a gdone-wait control: the put kernel has no gdone waits; it is also only defined under LG_L2A_BYPASS=1) and `LG_NEGCTRL_ISO` (GEMM isolation): `lg_r6x.hpp` statically refuses both ("r6x: L2b only"), unchanged from r13.
- **Not applicable to the put path (GEMM-side publish controls, inherited entries only):** `LG_NEGCTRL_NOWB`, `LG_NEGCTRL_NOCAS` act in `x_publish` of the GEMM entries; `lg_put_v1` has no publish. They compile (the inherited entries are unchanged) but cannot perturb the r18 pipeline. The r18 analogue of "S not written back before the put" is assumption A1 (O1): its control would be a put kernel launched WITHOUT the stream dependency on the GEMM, which is a host-level test, not a flag.
