# large/r13 — per-launch m_real (R16 option b, masked tail) on top of large/r12 (source only, UNCOMPILED)

INTERNAL-ONLY. Implementor-LG. Spec: records/architecture/stage3/R16-pad-m-design.md option (b) + the user's rule: "the kernel only gets the valid m; the padded m only selects the kernel/plan". Base: large/r12 at aiter 36256e5d (r12 untouched). No compile/GPU: everything is unverified until Evidence builds it. r12 semantics kept: sticky ERR, tags, quiet_ready NaN fill, LG_TAG_EARLY / LG_POLL_BATCH / LG_QR_WGS, the seams.

## ABI / entry points
- `interface/lg_comm_abi_v4.h`: `LG_COMM_ABI_VERSION 5`, `LgCommArgsV4` = V3 + `m_real` @352 + `pad4` @356 (360 B). The plan geometry (tiles, chunks, n / half_first, grid, windows, K counts, plan code, arrival counts) is unchanged and comes from the bucket `M` (args.M, args.chunks = M/256).
- Host: `lg_comm_launch(..., call_id, m_real, stream)` (-105 unless 1 <= m_real <= M). Shared `lg_fusion_driver.cpp` (r12 builds unchanged behind `LG_COMM_ABI_VERSION`): **`lg_launch_v2` keeps working** (m_real = M: every bucket row valid, bytes identical to r12) and **`lg_launch_v3(..., half_first, call_id, m_real, stream)`** is new. `lg_abi_info_v1` reports ABI 5 and sizeof 360.

## What uses m_real (data) and what does not (geometry)
1. **A / Ascale:** the A buffer descriptor is `rows_avail * strideA` with `rows_avail = max(m_real - row, 0)` (3 bodies), so rows >= m_real read as zeros and never touch memory past the caller's tensor (a chunk entirely >= m_real gets a 0-byte descriptor). Ascale: `as = (row_idx < m_real) ? a_scale[row_idx] : 0` in `load_as` and the inlined load of the IK/IQ/normal tile body. MFMA on dead rows still runs (allowed).
2. **Stores:** see r13b below (the first version, a per-lane early `return` in the store functions, was replaced).
3. **Row base:** BOTH the staging slab stride S_d and the R source stride are `m_real` rows: R[src*m_real + m], S_d[m]; the receiver sees a contiguous `R[:4*m_real]`. (S window and R window keep the bucket size; m_real <= M fits.)
4. **Put length:** `r6x_put_group` copies `live = rows of the group's chunks that are < m_real` (`r13_live_rows`), destination offset `c0*256` rows (every earlier group is full whenever this one has a live row), and returns false when `live == 0`. **A group with no live row issues NO put** (deviation from "zero-byte puts": a linear COPY packet encodes `count-1`, so a literal 0-byte copy would underflow if it ever reached the ring; CCO's dispatch also returns on a 0-byte copy, cco.hpp l.1525), but the poster still passes its `gdone` wait (the dead chunks' items still run and publish), the credit wait/tag check and releases its arrival, so arrival/credit counts, the e+1 chain and all order proofs are unchanged. `inline_posts` (report[2]) now counts issued puts only (3 x groups with live rows).
5. **Tags:** `E = (STEP << 32) | ((m_real-1) << 19) | (call_id & 0x7FFFF)` (`LG_TAG_*` in the ABI header; m_real in 1..8192 fits 13 bits, static-asserted). Ranks that disagree on m_real present different tags: the credit-tag check (before any put) raises `TAG_CREDIT 0x31`, the arrival check `TAG_ARRIVAL 0x32`. **The runtime's static call_id uniqueness check must hold on the low 19 bits.**
6. **NaN fill (quiet_ready, r12c):** covers only `R[:4*m_real]` = `8*m_real*F` bytes (the reuse pad past it is never read).
7. **Config guard:** `m_real != 0`, `m_real <= M`, `pad4 == 0` added.

## Static proof (every allowed chunk count)
`lgc::r13_live_ok<NP,HG>(chunks)` (plain constexpr mirrors of group_first / group_nchunks) is `static_assert`ed for n1 {1,2,4,8,16,32 chunks}, n2 {2..32}, n4 {4..32}, n2h {2..32}, n4h {4..32}, n3q {8}: for EVERY m_real in 1..chunks*256 the live rows of the groups sum to m_real and form a contiguous prefix (no live row after a non-full group => R[:4*m_real] contiguous). `tests/mirror_r13_live_rows.py` is the independent mirror (OK at source time, also checks the tag packing fits 32 bits). The existing r7/r9 order proofs are unchanged (geometry unchanged).

## Gates for Evidence (suggested)
- **G-M0:** `m_real == M` => R byte-equal to r12 (same inputs; only the tag word differs), all n / half-first / n3q, dense/indexer/reuse.
- **G-M1 (exact vs bucket):** for odd m_real in {1025, 1100, 1279, 2049, 4097, 4351} (bucket plans M_b = ceil256): R[:4*m_real] byte-equal to the r12 result at M_b on an x zero-padded to M_b rows, row (s*M_b + m) vs (s*m_real + m), m < m_real; m_real multiple of 256 vs the exact-row plan.
- **G-M2 (no OOB):** x / x_scale allocated with exactly m_real rows followed by a poisoned guard page / canary: no read past the end (compute-sanitizer or guard page).
- **G-M3 (rank disagreement):** one rank launches with a different m_real => TAG_CREDIT 0x31 on the receiving peers, no put issued, ERR propagates (sticky), R[:4*m_real] NaN after quiet_ready; clean afterwards after reset().
- **G-M4 (dead chunks):** m_real small relative to M (e.g. 1 and 257 with M = 2048): groups without live rows issue no put, arrivals/credits still complete (no W2 timeout), report[2] = 3 x live groups, ERR 0.
- **G-M5:** NaN fill under ERR touches only R[:4*m_real] (canary after it unchanged).
- Timing gate of the design: C(m_real) <= B(m_real) - 5 % at m_real in {1025, 1100, 1279}; MFMA on the dead rows of the last 256-row tile is the only extra cost (<= one chunk GEMM).

## Risks / unknowns
- Uncompiled; the three `const int M = args.M` in the bodies are now unused (warnings only). `store_c_ptpc` early `return` inside the per-em lambda is after the collective shfl (lanes reconverge at the next lambda call). The dead-row Ascale value 0 and the masked stores make dead rows invisible; A rows >= m_real are zero by the buffer bound (the OOB-returns-zero behaviour of buffer loads is the mechanism r12 already relied on at the bucket edge).
- Python side (aiter-integrator): bind `lg_launch_v3`, pass m_real, size R views as `[4*m_real, F]` (reuse strided view T = 4*m_real), refresh the pins (`LARGE_SRC_SHA["r13"]`), the 19-bit call_id uniqueness check, and ATOM passes m_real. The reuse compact layout's pad semantics are unchanged (the pad after R[:4*m_real] is never read).

## r13b (register fix after Evidence's ISA finding: r12 VGPR 253-255 / 0 spills -> r13 VGPR 256 / 112 spills on n1/n2/n4/n2h/n4h)
Hypothesis (inference; Evidence measures): the r13 epilogue added DIVERGENT CONTROL FLOW around the live accumulators (a per-lane early `return` inside each unrolled em iteration of `store_c_ptpc`/`store_c_ptpc_multi`, conditional Ascale loads), which splits the straight-line epilogue into branches with all accumulators + packed values live across them. r13b removes every branch from the epilogue and keeps the K loop untouched:
- **Dead-row stores are redirected, not skipped:** `dst = (row < m_real) ? c_slab + off : dump` (one `v_cmp` + `v_cndmask` pair per 16 B store, no branch). `dump` = a fixed 16 B line at the start of the S-window pad (`S + 4*M*F` elements; the window is `roundup(max(P + >= 4 KiB, ...))`, the slabs use `4*m_real*F*2 <= P` bytes, the pad is never read or sent). Many lanes writing the same 16 B line is a benign race. IK/multi stores redirect every slab store of a dead row.
- **Ascale:** `a_scale[min(ri, m_real-1)]` (a `v_min`, no conditional load); dead rows read the last live entry and their results go to the dump line.
- **m_real is an SGPR value:** `mr = readfirstlane(args.m_real)` once per body; the A buffer bound `num_records = max(mr - row, 0) * strideA` is a scalar computed once per tile (OOB loads return 0, no per-lane mask); nothing m_real-dependent is evaluated per lane inside the K loop (the K loop is textually identical to r12).
- Attribution knobs for Evidence's ISA A/B (defaults 1 = r13b): `LG_R13_STORE_MASK=0` (no redirect) and `LG_R13_ASCALE_CLAMP=0` (r12 Ascale load) — correct ONLY when m_real == M, for register/ISA attribution, never production. If the spills persist with both 0, the cause is elsewhere (e.g. the A bound or `readfirstlane`): compare against r12 at the same flags. Plan constraints unchanged (VGPR must come back to ~253-255, spill 0, scratch 0; if it does not, fall back to masking only in the self-tile path with S slabs of bucket stride).
- **n3q:** the source is intact (`lg_r9_gemm_n3q_v1`, quarter_body, dispatch). It is the real kernel only when `LG_X_INDEXER=0`; for `LG_X_INDEXER=1` it is a trap stub (VGPR 0 / LDS 0) EXACTLY as in r12. A VGPR-0 reading in r13 therefore means that build was the indexer build; r12's VGPR 251 reading is the dense build. Please compare the same flag family.
- Ruled out as causes (K loop unchanged): the A buffer bound (SGPR), `slab_elems`, the tag, the poster/quiet_ready changes (separate kernels or non-GEMM code).

## r13c (register fix, second hypothesis; lead-approved)
`ptpc_cast`, `store_c_ptpc` and `store_c_ptpc_multi` were plain `inline __device__` in r12 and r13/r13b, i.e. inlined at the compiler's discretion. r13/r13b made the two store functions larger (m_lim + dump parameters, a select/branch per store); if the inliner stopped inlining them, the accumulators are saved around a real call (callee-saved VGPR spills + a stack frame), which matches Evidence's 108-118 VGPR spills / 448-464 B scratch on all five entries and n3q. r13c makes all three `__device__ __forceinline__` (no semantic change). Evidence check: no `s_swappc_b64` in the GEMM entries, `.amdhsa_private_segment_fixed_size` back to 0, VGPR back to ~253-255. If the spills persist, the knob A/B (LG_R13_STORE_MASK / LG_R13_ASCALE_CLAMP) and the A-descriptor / epilogue hypotheses remain.

## r13d (Evidence ISA findings on r13c: 2 `s_swappc_b64` in n2/n4/n2h/n4h/n3q, 108-118 VGPR spills everywhere; knob A/B with STORE_MASK=0 + ASCALE_CLAMP=0 did NOT clear the spills)
- **Calls (Finding 1):** the callee is `mori::cco::ccoSdmaDispatchPut` (MORI `inline`, not forced), inlined in r12 but not in the NP>1 posters of r13. The poster `for g < NP` loop gets unrolled and duplicates the put sequence; r13 added the live-row computation + early-out to it, which plausibly pushed it over the inline threshold. Fix: `#pragma clang loop unroll(disable)` on that loop (ONE inlined copy of the put). Expected: no `s_swappc_b64`, no SGPR spills (13/21) in n2/n4/n2h/n4h/n3q.
- **Post-loop optimization barrier (kept; semantically a no-op):** in the three item bodies `int mre = mr; asm volatile("" : "+s"(mre));` after the K loop; the epilogue uses `mre` (Ascale clamp, dead-row compare, slab stride) and the dump pointer gets the same barrier, so LICM cannot hoist their per-lane results above the K loop. NOTE: the lead's knob A/B (both mask knobs off still spills) refutes this hoisting as the MAIN cause of the VGPR spills; the barrier is kept only because it is harmless by construction.
- **Attribution knobs (default 1 = r13d; each 0 is correct ONLY at m_real == M, A/B only, never production), passed by build_device.sh so Evidence can attribute in one compile pass:**
  - `LG_R13_ABOUND=0`: the A buffer descriptor uses r12's EXACT expression `(M - row) * strideA` (bucket M) instead of `max(m_real - row, 0) * strideA`.
  - `LG_R13_MR_SGPR=0`: no `__builtin_amdgcn_readfirstlane`; `mr = args.m_real` read plainly like r12 reads M.
  - `LG_R13_RSTRIDE=0`: the S/R slab stride (`slab_elems`) and the put slot use M rows like r12 (R base with M instead of m_real).
  - existing: `LG_R13_STORE_MASK=0` (no dead-row redirect), `LG_R13_ASCALE_CLAMP=0` (r12 Ascale load).
  With ALL FIVE at 0 the GEMM entry code should be r12-equivalent except for the kernarg struct size (360 B vs 352 B) and the tag/poster code; if spills remain then, the cause is outside the m_real masking (e.g. the V4 args struct, `args.pad4`/guard terms, the poster/quiet code in the same kernel, or tag_E) and the next bisection is the r12 -> r13 diff of lg_r6x.hpp (poster) and the guard.

## r13e (r13d did not compile)
The post-K-loop optimization barriers of r13d (`asm volatile("" : "+s"(mre))`, `asm volatile("" : "+s"(dump_p))`) hit a backend fatal "illegal VGPR to SGPR copy" at the `dump_p` barrier (a 64-bit pointer forced into an SGPR constraint whose value the compiler had in VGPRs). The lead's A/B had already refuted the hoisting hypothesis they were meant to test, so BOTH barriers are removed: the epilogue is back to the r13c text (plain `mr`, `const dump_p`), with r13d's `unroll(disable)` on the poster loop and the attribution knobs (LG_R13_ABOUND / LG_R13_MR_SGPR / LG_R13_RSTRIDE / LG_R13_STORE_MASK / LG_R13_ASCALE_CLAMP, default 1) kept. No `asm volatile` remains in the kernel TU. Lesson recorded: an `asm volatile` with an "s" constraint on a value that may live in VGPRs is not a safe optimization barrier on AMDGPU; if a barrier is ever needed, use no constraint ("memory" clobber) or compute the value through `__builtin_amdgcn_readfirstlane`.

## r13f (Evidence matrix on r13e: spills unchanged, 674-681 total, also with ALL five mask/descriptor knobs at 0)
With STORE_MASK / ASCALE_CLAMP / ABOUND / MR_SGPR / RSTRIDE all 0 the item code is r12-equivalent, so what the knobs did not cover is: the args struct (V4 = 360 B vs 352 B), the guard terms, and the poster/tag/put code. r13f adds the two missing knobs (default 1, `=0` = r12 behaviour; each 0 is correct ONLY at m_real == M; A/B only, never production):
- **`LG_R13_POSTER=0`**: r12's poster/tag/put code EXACTLY: `tag_E = (STEP << 32) | call_id` (no m_real), `r6x_put_group` copies full-bucket groups with slot `2*M*F` and always returns true (no live-row computation, no skip-put path), no `unroll(disable)`. The `did_put` accounting folds to unconditional.
- **`LG_R13_ARGS=0`**: the struct is the V3 layout (352 B, no `m_real`/`pad4`); every device/host use of m_real becomes M (`LG_MREAL(a)`), the guard drops the m_real/pad4 terms, the host does not write the field. `build_host.sh` and `build_device.sh` both pass it (HOST AND DEVICE MUST AGREE).
- **Bisection matrix for Evidence (one compile pass):** (1) all seven knobs 0 + the r13 sources = r12 behaviour modulo type/macro names, `r13_live_ok` static asserts and the V4 rename: if THIS still spills, the cause is outside everything m_real-related (toolchain, header/include text differences, or the r12 baseline itself); (2) enable one knob at a time (POSTER, then ARGS, then ABOUND / MR_SGPR / RSTRIDE / STORE_MASK / ASCALE_CLAMP) and watch the first jump of VGPR/spills/scratch.
- **Structural fix (host-precomputed per-group live rows / offsets, the tag low word as a kernarg, a scalar no-put branch) is NOT implemented in this commit:** I am not confident the poster sets the footprint (it is one block executing scalar-ish code on lane 0; the persistent kernel's peak is the K loop/epilogue) and it would enlarge the args struct, which is itself one of the suspects (ARGS knob). If POSTER=0 or ARGS=0 is the first jump, the host-precompute becomes the next commit: `u32 grp_off_rows[4]`, `u32 grp_live_rows[4]`, `u32 tag_lo` in the args (8-32 B), the poster reading them as plain loads (no arithmetic), the no-put branch on `grp_live_rows[g] == 0` (scalar), and the host computing them with `r13_live_rows` (already shared constexpr).

## r13g (ladder result: steps 0-5b == r12 (0 spills); step5c, i.e. passing `mr`/`dump_p` to the store call sites + the `dump_p` declarations, alone causes VGPR 256 / ~663 spills, even with all knobs 0)
The cost is liveness of extra per-call values through the epilogue, not the masking behaviour. r13g removes ALL new data flow into the item epilogue (option (a) of the lead):
- **Epilogue + call sites are r12 text again** (`epilogue_ptpc_pairstore.hpp` = r12 renamed, no `m_lim`/`dump`, no masks, no `dump_p`; the store calls are r12's). Obsolete knobs (ignored; macros left in the ABI header): `LG_R13_STORE_MASK`, `LG_R13_RSTRIDE`.
- **S slabs keep the BUCKET stride M** (`slab_elems = M*kFS`, as r12): the dead rows of the tail chunk (rows >= m_real, computed from zero A rows) are stored harmlessly inside their slab and never sent (the put copies only live rows).
- **Put compacts:** `r6x_put_group` reads from the bucket-stride S slab (`peer*2*M*F + c0*256 rows`) and writes the live rows to `rank*2*m_real*F + c0*256 rows` of the receiver's R, so the receiver sees a contiguous R[:4*m_real] (empty groups still issue no put, arrivals unchanged).
- **Self tile:** for a FULL bucket (`m_real == M`, e.g. every exact-multiple shape) the self tile is written straight into R exactly like r12 (one scalar compare in `slab_of`; folds to r12 with `LG_R13_ARGS=0`). For `m_real < M` the self tile goes to the free S slab `rank` (bucket stride) and `quiet_ready` compacts it into `R[rank*m_real ..]`: `r13_copy_self` (16 B grid-stride copy, no inter-WG wait) is run by the helper WGs at their entry (while WG0 waits for the peers' arrivals: hidden behind W2) and by WG0 at its end (the only share when `LG_QR_WGS == 1`). It is skipped under ERR (the NaN fill takes over). Cost: only m_real < M launches pay an extra read+write of m_real*F*2 B (inference: ~10 MB at M2048-class, overlapped with W2).
- Kept from r13f: m_real in the tag, A bound / Ascale clamp / readfirstlane / poster knobs (`ABOUND`, `MR_SGPR`, `ASCALE_CLAMP`, `POSTER`, `ARGS`, default 1), `unroll(disable)`, the NaN fill over R[:4*m_real]. NOTE: the ladder ran with ALL knobs 0, so steps 5a/5b with `ABOUND`/`MR_SGPR`/`ASCALE_CLAMP` = 1 are not yet register-verified: if the default build still spills, bisect those three next (they are scalar/`v_min` only).
- **Gates (additions):** G-M0 m_real == M: byte-equal to r12 AND no self copy (device behaviour == r12 + one scalar compare); G-M1 odd m_real: R[:4*m_real] byte-equal to the r12 result at M_b on zero-padded x (self rows included: they now arrive via the copy); G-M6 LG_QR_WGS = 1 and 64 with m_real < M (self rows complete before the kernel ends); under ERR the copy is skipped and R[:4*m_real] is NaN.
