# PR #7410：最新 main 对照下的 EP4 S1F T16384 优化

本轮只比较 V1 与 V3，取消 V2。最新完成的正式对照使用干净 main `88ebffa40126277787d523a50632fe8d03d3dc9a` 与 V3 commit `e5abbda6ac12ea9d36a500451ab02445bbae87fc`。三轮交替测试的 median 为 V1 `1695.985844`、V3 `1606.463250` µs/layer，降时 `5.278499%`。六次原 accuracy gate 全部 PASS，三轮四 rank 的完整输出共12项均与同轮 V1 bit-identical。完整八层 graph 降时超过20%的目标尚未达到；main95对照与单轮筛选均作为历史数据单独标注。

撤回前的 S1F SiLU FMA 配置三轮 median 为 `1601.414219` µs/layer，V1 为 `1747.273031` µs/layer，降低 `8.347797%`；只设置 pin，没有使用 tile、APRE 或 producer 调优 overrides。该数字不代表最终原舍入配置的成绩。保留原舍入次序的 chunk4/8/16 单轮分别为 `1609.108437`、`1604.961813`、`1604.498000` µs/layer，三项四卡完整输出均与 V1 bit-identical。

当前正式默认使用 G1 row-major input / APRE A2，G1 为 M256/N256/K256/w2x2/b3、prefetch0；G2 为 M256/N256/K256/w2x2/b4、四个 TDM owner waves。实验文件名 `kernel_g2_b4planarwpt4.py` 中的 planar 不是实际布局：该 G2 分支使用非 planar、非 interleaved LDS。V3 的 pin VGPR 保持开启。

历史 main95 的 V1 不能标为严格 main 原样。main95 在当前环境编译 row-major M256/1x4 时，会对超出 128 dwords 的 operand slot 启用 pin，触发 `make_rmem_slot()` 的断言。该 geometry 的 slot 是 `16*8 + 2*16 = 160` dwords。因此当时远端独立 main 实验 worktree 只加入了 geometry guard：超过 128 dwords 时使用自动分配，合法 M256/2x2 仍允许 pin。补丁为 `main_register_guard.patch`，失败原样日志在 `cases/v1_screen_0`。这部分数据的准确名称是 **main95 + VGPR geometry guard**。

V1 的 env pin=0 不代表全部 kernel 无 pin；main 也会根据 tile 自动选择。V3 明确设置 `AITER_FLYDSL_EXPLICIT_VGPR_PARTITION=1`。

main88 包含 #7973，将普通 M256 S1F 的 wave geometry 修复为2x2。合入目标分支时保留 APRE 的显式 geometry 参数；普通 S1F 遵循上游2x2选择。新 V1 已直接使用干净 main88，三轮均编译及运行成功，无需 geometry guard。main95 数据不能作为 main88 的基线。

## 测量与数值口径

计时沿用原 benchmark：每次 replay 完整八层，20 次 host wall-clock 样本；各 rank 取排序后的 `[10]` upper median，四 rank 平均后除以 8。这包含 RMSNorm/residual、replay 和 sync 开销。正式验收逐版本取三轮独立进程的 median；分项不相加充当总耗时。

所有版本复用相同的 quantized weights、input 和 routing，并保存 SHA256。FP32 reference 仅在输入、routing、层数及 reference source hash 完全相同的情况下复用；原 acceptance tolerance 保持不变。性能前后均检查全部 GPU，等待时每 6 秒复查；计时中不运行 GPU telemetry。

### GEMM1 动态成对 N-panel queue 原型

实验保持G1 M256/N256/K256/w2x2/b3、原SiLU舍入与chunk16、全部input waits及最终output drains。256个WG按两个相邻N panels组成128个physical clusters，只有peer0领取下一ticket；一条自然8-byte对齐的atomic i64编码`(generation<<32)|ticket`。另一peer使用现有system-scope monotonic load读取该word，检查generation及递增ticket。每个G1 tile的DS/WG handoff后执行cluster rendezvous，防止sender覆盖尚未读取的message。row-major A使用multicast，ScaleA仍为private load。`early_timeout=0`使用standard hardware timeout，不能解释为完全没有timeout。

初次CPU compile暴露误传内部`tdm_early_timeout`选项以及loop-carried SSA初始化问题，均在启动GPU前修正。修正后的CN1 rank0及CN2四rank CPU compile全部PASS，实际ELF为block128、VGPR848、VGPR spill0、scratch0、dynamic LDS221440 B（分配对齐后223232 B）；SGPR spill分别为CN1 52、CN2 47。四个CN2 ELF都包含`cluster_dims=2,1,1`，任务map与资源静态审核PASS。

| `v3_formal_pairq1_screen_0` | 1，对照 | 1605.344000 | PASS |
| `v3_formal_pairq2_screen_0` | 2，paired queue | 1595.148250 | PASS |

H5120 的每个 BF16 payload 为10240 B，原 slot pitch 为16384 B。原 GEMM2 将 `(peer, slot)` 合为一条 u32 TDM row index，要求 CCO peer VA stride 能被 slot pitch 整除；直接把 pitch 改成10240 B 会破坏该地址公式。临时原型保留所有计算和 waits，改用2048 B地址单位：`index = peer * (perRankSize / 2048) + slot * (pitch / 2048)`，TDM global row stride为2048 B，N panel 的原 byte offset保持不变。比较16384 B地址算法对照与10240/12288/14336 B三种pitch；M256 tile、pin、G1及combine求和顺序均不变。

四种 CPU-only compile和reduce compile均PASS，实际GEMM2 ELF均为block128/wave32、VGPR832、SGPR78、SGPR/VGPR spills0、scratch0、builder LDS278528 B；text为35200–35328 B。四项静态指令数量一致：768 WMMA、24 input TDM、8 TDM stores、36 tensor waits、58 DS waits、14 WG barrier signal/wait pairs。kernel、recipe与type的整棵AST在还原唯一任务gate和stride变换后与正式源码一致。

CPU模型逐一核对四rank全部98304个slots及20个N256 panels的地址、唯一性和payload边界。`required_vmm_bytes`请求的每rank VMM分别为2801795072、2197815296、2399141888、2600468480 B；Mori `/app/mori/src/cco/cco_init.cpp:619–627` 会将实际 `perRankSize` 再向4 GiB对齐，因此本组均为4294967296 B，descriptor height为8388608，小于2^31。这里区分arena所请求的VMM字节数与实际peer VA stride。padding/dropped sentinel仍为descriptor的OOB行，所有合法addresses保持原peer和slot对应关系。

首轮CPU compile误将所有raw placeholders设为byte alignment1，ScaleA的`fx.Int32` recast因需要4 B对齐而失败；随后按实际pointer ABI使用A/B alignment1、C alignment2、ScaleA/ScaleB/maps alignment4修正，未更改正式源码或GPU输入。首轮ISA审核的regex还漏掉了紧接操作数的`//`注释，修正parser后按完整反汇编重算全部指令数量；没有降低编译或资源门禁。

## 移植与适配

已移植 native compute、固定 operand/ring 地址、operand reuse、4×4 clustered persistent 及 compatible next-N 逻辑。CSV 仅加入源 E64/E65 T16384 的五条相关配置。S1F 动态下一项任务没有被假设为相邻 N。

已修复 APRE scale TDM 的 global/LDS majorness 不兼容、resident ring phase 的 constexpr 展开、短 M body 的 pinned scale slot，以及 claim SSA 在 M-tail 分支外使用的问题。APRE mode2 由 TDM 转换 FP4 A，scales 使用既有 row-major LDS lane addressing。

保留 dropped-route masking，使用已有 `Routing.topk_ids` 传递 source IDs。combine 的候选优化让对齐到单一 token 的 block 使用 uniform routing-ID 地址，累加次序和 NaN dropped-slot 处理保持不变。

APRE full-ring prefetch 的 deferred C 候选新增独立输出 staging，保留原重叠断言和退役协议，不以删除断言解决 LDS 重用冲突。G2 cluster 设置可以通过既有阶段 env `AITER_FLYDSL_MXFP4_CLUSTER_M1/N1/M2/N2` 单独调整。

最近新增候选包括 CM1/CN4 persistent GEMM2，以及 row-major G1 input / APRE A2 的独立布局。它们仍处于筛选，不能标为最终默认配置。row-major input 的前两次尝试触发 claim SSA dominance 编译错误（`v3_rminput_screen_0`、`v3_rminput_nopref_screen_0`）；已将对应 M-tail 路径的 claim 移到所有分支之前再验证。失败日志均保留，未用失败运行中的耗时。

新增的非 resident pin 候选将 C 放在 v64 起的区间，并将两个 operand slots 按实际 geometry 紧接在 C 后面。M256/2x2 的单 kernel VGPR 从 1024 降至 832；这只是资源变化，不代表耗时收益。clustered resident 的固定 ring 布局仍单独保留。

G1 的 M256/2x2 S1F 支持三或四个 input buffers，cache key 包含 buffer 数；三 buffer 路径也允许八 slot producer ring。H5120 combine 的 block 改为 320 threads，使一个 block 仅访问单个 token，两个 block 覆盖该 token 的 640 vector lanes。累加顺序、dropped-route mask 和 shared-add rounding 保留。
