Source review and boundary choice
MoE routed/shared outputs are combined and TP-reduced, then the next layer's
mHC post/pre path produces normalized attention input. Baseline already uses
2 gfx1250 Gluon launches: residual mixing + split-K HC projection/square sums;
then partial reduction + sigmoid/Sinkhorn20 + HC weighted sum + RMSNorm.
Attention wqkv_a separately quantizes this BF16 input in groups of128.
Compressor consumers also need the BF16 activation, including side streams.

Implementation
Extend the second existing mHC launch to emit FP8 e4m3fn payload and column-major
E8M0 per128 scales, retaining the BF16 output. Quantization rounds the normalized
value to BF16 first, uses HIP's ceil-power-of-two RoundUp scale and 1e-10 floor,
and emits the exact existing consumer ABI. It removes60 quant launches/step.
Keep stage1 and stage2 separate: kernel completion orders their partial buffers;
no new cross-CTA flags, peer mailboxes, epochs or cross-rank synchronization.
Each epilogue CTA owns whole rows. Maximum supported fused rows128.

For wqkv_a [N2048,K7168], use the existing public AITER gfx1250 Gluon
bandwidth-bound preshuffled FP8 GEMM through64 rows. It uses existing tuned JSON
configurations and adds a split-K reduction launch. No weight repacking or MoE
changes. Above64 rows, retain baseline GEMM because M128 microbench regressed.
The retained projection consumes [M,K] FP8, column-major activation scale bytes,
[N,K] preshuffled FP8 weights and [N/128,K/128] E8M0 weight scales; it overwrites
BF16 output after its partial reduction. Original attention side streams remain.
Kernel count rises by1/step overall: remove60 quant launches, add61 split reductions.
This is a hybrid implementation, not a fully fused attention+MoE layer kernel.

Integration and fallback
ATOM_DSV4_HYBRID=1 enables fused mHC/quant, ATOM_DSV4_HYBRID_GEMM=1 also enables
projection dispatch. Both default off. ATOM_DSV4_HYBRID_MAX_TOKENS caps fusion
at128. Eligibility guards require gfx1250, HC4, supported hidden dimensions,
FP8 E8M0 preshuffled dense weights, and full-graph mode. Unsupported contracts
retain baseline. Concrete row dispatch occurs inside opaque custom ops so the
large compile warmup cannot specialize away decode paths. Large-row mHC uses
original post/pre plus original HIP quant. Projection >64 uses original GEMM.
ATOM_DSV4_HYBRID_CHECK=1 checks first16 eligible calls per rank outside capture.

Profiling method and evidence
Walk GPU forward annotations backward from trace end until last prefill/mixed
prefill. Aggregate every contained GPU kernel across all50 pure decode steps;
do not infer boundaries from CPU launch timestamps. Full names, counts,
mean/median/min/max and total microseconds are in analysis/*/kernels.csv.
Capture-trace mapping attributes kernels to model operators in operators.csv.
GPU union time accounts for overlapping streams; summed durations do not equal
critical-path latency. Every TP rank is analyzed.
Final profiles show3000 fused mHC epilogues over50 steps per rank (60/step),
plus3050 split-K projection/reduction pairs (61/step), at concurrency16 and64.
Rank0 profiled decode wall: c16 24.232->17.939ms; c64 23.983->17.544ms.
These are profiled diagnostics, not the final serving latency metrics.

Experiment caveats and rejected attempts
Initial graph256 warmup failed with HIP200 invalid device image in topk;
standalone reproduction passed. Separate cache and128 maximum were used for
both measured arms. See design-log.txt and startup logs.
The first hybrid_quant serving attempt specialized away the new path during
outer-model row dispatch. Its traces have FUSE_QUANT_0 only; those measurements
are explicitly excluded as hybrid evidence. Final traces use FUSE_QUANT_1.
Kit s_memrealtime probe was unsupported; the wall-clock port was inconclusive.
No host-descheduling claims are based on that probe.

are small, with a slight regression at concurrency1. No statistical confidence
claim is made for the smaller changes. The final control's four deterministic
completions also match the hybrid exactly. Servers were stopped after testing;
the modified container remains available with no KFD processes running.
