一、Task1：OPUS A16W16 Split-K Workspace Torch 化

需求和目标

  • Python 在分配 workspace 前统一解析 explicit、tuned CSV、架构 heuristic、framework fallback，得到最终 actual_kid 与 split-K。
  • workspace 所有权从 C++ 全局/按 stream registry 转为调用级 Torch Tensor；支持自动分配和 caller Tensor 原样复用。
  • 删除 C++ 内部 allocator、handle、device mirror、预热和隐藏缓存，kernel 与 reducer 直接接收 workspace pointer。
  • 以 exact-kid metadata 决定 capability、shape、BF16/FP32 storage 和 two-stage/fused launch，并保留 generated C++ 最终物理校验。
  • 统一 gfx942、gfx950、gfx1250 two-stage 与 gfx1250 fused actual-kid 流程；保持 graph、stream、调用级生命周期。
  • 修复 gfx950 mono-tile FP32 写回，并把最终生产 raw 边界切到共享同一 checked launcher 的 C ABI/ctypes 路径。

二、Task2：OPUS GEMM Family-Specific Canonical 接口重构

需求和目标

  • 保持 gemm_a16w16_opus 与 Task1 workspace/fused 行为不变，把 C++、pybind、Python 对齐为四条 family-specific canonical launch。
  • Python 是 A16W16 唯一 runtime policy 层；C++ 只做 current arch、family、dtype、exact kid 的安全路由。
  • 把 A8W8 no-scale、plain-WQ blockscale、blockscale-bpreshuffle 拆成三个独立物理合同和 typed table；两个 scale 参数改为必选。
  • gfx942 bpreshuffle 保留 kid 11000；gfx950/gfx1250 保留稳定同名 ABI 和可编译空 capability，不借用其他架构 kid。
  • 删除 generic C++ opus_gemm、旧 C++/pybind tune、runtime shape lookup 和 C++ heuristic；旧 Python tune 名仅为 deprecated adapter。
  • 迁移仓内调用方和 tuner，并保留 CSV、sidecar、heuristic defaults、mandatory A8 kids 组成的 subset compile 可达性。
