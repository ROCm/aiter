1. “全量通过”的定义

本文的“全量”限定为 Task1/Task2 影响到的 OPUS 接口、A16/A8 family、workspace、 exact-kid dispatch、Graph/stream 和性能，不表示整个 AITER 仓库所有算子都已执行。 全量结论必须依次通过以下门：

合同与生成门registry、接口、codegen、workspace 计划、subset compile、跨架构拒绝。
目标 GPU 正确性门代表性 GPU 测试加该架构全部 canonical kid；目标架构不得 skip。
性能门同机、同环境、同输入、独立 JIT 端点，按 ABBA 顺序分层比较并先做数值断言。
状态只能使用：PASS、FAIL、NOT RUN、 BLOCKED。目标架构 skip、无空闲 GPU、缺历史端点或只做 CPU/codegen 检查都不能写成 PASS。

4. 一次 fresh build，随后固定同一模块

exhaustive runner 必须使用包含当前架构全部 canonical A16 kid 的模块。先生成 sidecar，再用 AITER_REBUILD=1 单进程构建一次；回归和性能阶段统一使用 AITER_REBUILD=0。 

python3 - <<'PY'
import json
import os
from pathlib import Path

from csrc.opus_gemm.opus_gemm_common import get_kernel_instance, kernels_list

arch = os.environ["OPUS_VALIDATION_ARCH"]
kids = sorted(
    int(kid)
    for kid, instance in kernels_list.items()
    if get_kernel_instance(arch, "a16w16", int(kid)) is instance
)
build = Path(os.environ["AITER_JIT_DIR"]) / "build"
build.mkdir(parents=True, exist_ok=True)
sidecar = build / "compiled_kids_opus.json"
sidecar.write_text(json.dumps(kids) + "\n", encoding="utf-8")
print(f"arch={arch} a16_kids={len(kids)} sidecar={sidecar}")
PY

  • 目标架构不匹配时 fail 或明确 NOT RUN；不能安静 skip 后签字。

8. ABBA 性能执行方法

统一口径：固定同一 CPU core；每 case warmup 20、9 rounds、每 round 100 次；每轮取 median。每次 endpoint 使用新进程。

8.3 只测统一 public 路由增量

在同一个当前 JIT 上按 task2 A1 → current B1 → current B2 → task2 A2 运行。 task2 直接走当前 private family，current 增加统一 opus_gemm router；这样 kernel、kid、workspace 和 C++ module 完全相同。 

set -o pipefail
run_current_interface() {
  OPUS_ENDPOINT="$1"
  OPUS_PASS_ID="$2"
  taskset -c "$OPUS_CPU_CORE" env \
    PYTHONPATH="$OPUS_CURRENT_SRC" \
    AITER_JIT_DIR="$OPUS_CURRENT_JIT" AITER_REBUILD=0 \
    python3 "$OPUS_INTERFACE_BENCH" \
      --arch "$OPUS_VALIDATION_ARCH" \
      --endpoint "$OPUS_ENDPOINT" --pass-id "$OPUS_PASS_ID" \
      --warmup 20 --rounds 9 --iters 100 \
    2>&1 | tee "$OPUS_LOG_DIR/router-$OPUS_ENDPOINT-$OPUS_PASS_ID.log"
}

run_current_interface task2 A1
run_current_interface current B1

9. 正确性与性能判定

9.1 正确性

  • pytest/assert runner：退出码 0、failed = 0、目标架构 skip = 0、输出与 workspace 均有限值。
  • 使用测试中按 family 规定的 tolerance；不得因为 upstream 某门更宽松，就把当前严格 gate 的失败改写成通过。
  • Graph、双 stream、caller workspace、自动 workspace 和错误合同分别记录，不能用 eager 数值代替。
  • MOE 不属于这两个 Task 的 OPUS 验收范围；若 PR CI 跑 MOE，应单独列为仓库级回归，不和本页 BMM/A16 结论合并。

9.2 BMM 的 failed! 与正式 gate

test_opus_a8w8_bmm.py 中的 checkAllclose 是诊断函数：逐元素 rtol=atol=0.01 超限时可能打印 warning! 或 failed!， 返回 mismatch ratio，但除 catastrophic error 外不一定让进程退出非零。因此“命令退出码 0”本身不是 BMM 严格通过证据。
  • shape sweep 必须保存每行 err、最大误差、NaN/Inf 和所用 kid/split-K。
  • all-kid m_align、tileN column-map、workspace/Graph guard 是 assertion gate，任何失败都必须失败退出。
  • 正式 tuner 使用 signed、分块变幅输入、FP32 dequant reference、rtol=atol=0.01， 并只保留 mismatch fraction <= --errRatio（默认 0.02）的候选。
  • 若项目要求“每个元素都在 1% 内”，必须另外使用 strict assert；不能把 tuner 的 2% mismatch-fraction gate 解释成逐元素全通过。

9.3 ABBA 统计

每个 case、每个层独立计算，不用总和掩盖单个退化：

A = median(A1, A2) B = median(B1, B2) delta = B / A - 1 repeat_drift = max(|A2-A1| / A, |B2-B1| / B)
  • |delta| <= repeat_drift：在本次观测噪声内，报告“未分辨出变化”，不要声称确定提升。
  • delta > repeat_drift：存在可分辨退化，必须定位到 public/private、raw、direct 或 Graph 层；未解释前为 FAIL。
  • delta < -repeat_drift：存在可分辨提升，仍保存两端重复漂移与逐 case 数据。
  • GPU 型号、CU/partition、时钟/功耗、ROCm、PyTorch、module SHA、shape、kid、split-K 或 workspace 不同的结果不能直接比较。
