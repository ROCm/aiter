Task2 功能与回归验收完成
gfx950A16/A8 原有路径接入与其他架构一致的 Python 选核和 kid 表。
Python 选核tuned CSV 与 per-arch heuristic 只保留在 AITER/Torch。
C++ 边界只保留启动所需检查、kernel 入口和 kid → launcher dispatch。
接口整理dtype、layout、scale 和输出合同按 kernel 类型拆开。

1. 最终验收结论

  • gfx950 A16 tuned miss 已由 Python heuristic 选择最终 kid；C++ 只按 kid 启动。gfx950 A8 no-scale kid 2 与 blockscale kid 1 也分别进入自己的生成表。
  • tune lookup 和 per-arch heuristic 只保留在 Python/AITER：先查 tuned CSV，未命中或配置无效时进入 Python heuristic，再失败才进入 framework fallback；C++ runtime shape/tune lookup 和 C++ heuristic 已删除。
  • 选核、dtype/layout/scale 路由、输出准备、split-K/workspace 和 framework fallback 均由 AITER/Torch 负责；C++ 只保留启动所需安全检查、kid → launcher 查询和 kernel launch。
  • generic C++ 入口已拆成 A16、A8 no-scale、A8 blockscale 和 A8 bpreshuffle，并固定各自的 dtype、layout、scale 与输出合同；当前 Python public 收敛为 opus_gemm()，后续 MXFP8 BMM 沿用同一边界。

2. 原本流程与当前流程

Task2 改造前

1. Python wrapper 先查一套 tuned 配置 gemm_op_a16w16.py / common.py::lookup_tuned() 根据 shape 查 CSV；显式 kernelId 或命中 tuned row 时进入旧 tune API。
↓
2. Python miss 后进入 C++ 的另一套策略
Python 命中把 kid/split-K 传给旧 A16/A8 tune entry。
Python 未命中_opus_gemm_bf16_dispatch() → generic C++ opus_gemm()。
↓
3. C++ runtime lookup Generated shape/tune lookup 再按 M/N/K、dtype、bias 等条件查一次；C++ 同时保存一份 runtime policy。
↓
4. C++ per-arch heuristic lookup miss 后进入 gfx942/gfx950/gfx1250 各自的 C++ heuristic，再决定实际 launcher 或 kid。
↓
5. dtype/layout 处理混在 generic 入口 A16 与多种 A8 路径共用或复用 generic/tune 参数，scale 可选，Python、pybind 和 opus_gemm.cu 的合同分散。
↓
6. GPU 执行 C++ 最终选择 launcher 并启动 GPU kernel。选核与 kernel launch 都落在 C++ 路径中。

↓
3. Python 整理 dtype/layout kernels_list.get(kid) 取得架构和 kernel 类型；dtype、layout、scale、bias 和 workspace 只做合同校验与参数准备，不重新选 kid。
↓
4. 进入对应私有启动函数
A16W16gemm_op_a16w16.py::_launch_a16w16()

↓
5. Torch 侧完成 framework 工作 上层准备 Y；A16/MXFP8 需要 Split-K workspace 时由 Torch Tensor 提供；Python 完成 shape、device 和调用参数组织。
↓
6. C++ 只做 kernel + kid dispatch 对应 raw binding 进入分开的 C++ launch API；opus_gemm.cu 只做启动所需安全检查，并按当前 arch、输出 dtype 和最终 kid 查询 launcher 表，不再执行 shape lookup 或 heuristic。
↓
7. GPU 执行 Generated launcher 最终检查物理 shape/stride/tile 条件后启动 kernel；Split-K 路径可归约到 Y。
