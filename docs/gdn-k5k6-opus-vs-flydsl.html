GDN prefill 融合 K5+K6：opus WF vs FlyDSL VK (PR #4884)

AMD Instinct MI308X · gfx942:sramecc+:xnack- · 80 CU · bf16 · K=V=128 · BT=64 · GQA 4（Hk=16 / Hv=64）· packed varlen · 两侧都是 output_final_state=True + 真实 initial_state · 每格 50 次取中位、profiler 20 次取 device time

这台卡不是 PR 的目标卡。PR #4884 把 FlyDSL VK 路径门控在 _device_cu_count() >= 304（MI300X/MI325X），本机 80 CU， 所以 fusion=AUTO 在这里永远不会融合——FlyDSL 列是用 fusion=ALWAYS 强制打开的。更要紧的是变体选择规则 _hn_variant 用的是绝对阈值（H·N≤32→bv16、 ≤80→bv32），不含 CU 项：在 304 CU 上这些阈值对应约一个 CTA wave， 在 80 CU 上却要求最多 3.2 个 wave。19/64 格因此选小了 BV， 平均损失 1.96x。 右侧「按 CU 缩放的变体」列就是把这一项修掉之后的结果。

按 B·H 汇总

B·H（序列数 × 每卡 value head 数）是唯一移动结果的变量：TP、seqlen、T 都只通过它起作用。CTA/CU 是 as-shipped 变体的实际网格占用 ⌈V/BV⌉·B·H / 80，超过 1 就是排队。

整块 pipeline 的 wall

K5+K6 之外两条 pipeline 的前端也不同：opus 把 K1..K4 融进一个 HIP kernel（gdn_k1_neumann_kernel），FlyDSL 融进 gdn_prepare_kernel，后者快 1.30x， 部分抵消了 K5+K6 的差距。

as-shipped 全 pipeline：geomean(opus/FlyDSL) = 0.918， FlyDSL 赢 25/64 格。 K5+K6 单看是 geomean 0.766（修正变体后 0.937）。
