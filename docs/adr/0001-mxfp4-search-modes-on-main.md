# Preserve main's MXFP4 search CLI and stage after pruning

The port extends `--mxfp4-search-mode` to `prune|full|staged`, keeping `prune` as the default and preserving existing prune/full candidate order, parallelism selection and scheduling/supervision mechanisms. The agreed correctness, metadata, CSV, runtime-device and effective-parameter repairs also apply to those modes; runtime-device preflight explicitly covers all three MXFP4 modes. Staged search operates on main's M_est-pruned, layout-v2-only candidate universe, as chosen during port planning; this keeps one public parameter and combines heuristic pruning with measured stage screening to reduce tuning work. Staged fallback remains within that pruned universe, so calibration must report full-to-prune, prune-to-staged and full-to-staged results separately rather than assuming full and staged search the same universe.
