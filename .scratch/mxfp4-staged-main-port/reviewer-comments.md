## User decision: configuration consistency belongs to the caller

The reviewer correctly identified that kernel names and CSV shape keys do not encode swiglu_limit or the two stage2 output switches. The tuner can therefore deduplicate or overwrite a same-shape result from another configuration, and production cannot infer those settings from the CSV. This risk remains a caller obligation by explicit user choice: “不用管这个问题，由调用方保障”.

The port retains the existing tuner limit environment variable and adds the already agreed AOT limit argument. The caller selects the appropriate winner CSV, avoids mixing/reusing results from incompatible settings, and supplies matching activation parameters and output flags to tuning, AOT and production. No JSON sidecar, prescribed sidecar format, automatic file/configuration binding, mismatch rejection or production runtime reader is introduced. The earlier sidecar/enforcement proposal was not accepted and is not an implementation requirement.

Calibration and acceptance continue to use separate output files and retain their actual settings in validation artifacts, as already agreed. These experiment records are evidence, not a new mechanism for policing deployed files.
